## 第3回 データの種類 { #w03 }

| 概念 | Excel | ノートブック（pandas） |
|---|---|---|
| 列が数値か文字か | **列には型がない。**セルごとの「表示形式」だけ | **列ごとに型がある**（`mydf.dtypes`／`object` ＝文字が混ざっている） |
| 選択肢を数える | `COUNTIF` | `value_counts()` |
| 順序尺度（満足度1〜5） | `AVERAGE` で**平均が出てしまう** | `mean()` で**平均が出てしまう** |

!!! warning "🔴 ここは道具のちがいではありません"
    **「満足度の平均」を止めてくれる道具は、どちらにもありません。**
    止めるのは、**設問を設計した人**です（[第3回 資料](week03-datatypes.md)）。

**ちがうのは気づき方です。**Excelは、数値の列に文字が1つ混ざっても表はそのまま出ます。
pandasは `dtypes` を見れば「この列は文字だ」と分かります。第6回で最初に `dtypes` を出したのは、そのためです。

## 第4回 代表値とばらつき { #w04 }

| 概念 | Excel | ノートブック |
|---|---|---|
| 平均 | `AVERAGE` | `mean()` |
| 中央値 | `MEDIAN` | `median()` |
| 最頻値 | `MODE.SNGL` | `mode()` |
| 標準偏差（標本） | **`STDEV.S`** | **`std()`** ← pandasの既定 |
| 標準偏差（母集団） | `STDEV.P` | `std(ddof=0)` |
| まとめて全部 | 分析ツール → 基本統計量 | `describe()` |

!!! warning "🔴 標準偏差は2種類あります"
    `[1, 2, 2, 3, 4]` で確かめた値（pandas 2.3.3 を実行）：

    - `STDEV.S` ＝ `std()` ＝ **1.140175**（標本。**どちらも既定はこちら**）
    - `STDEV.P` ＝ `std(ddof=0)` ＝ **1.019804**（母集団）

    **ただし `numpy` の `np.std()` は既定が母集団のほう（1.019804）です。**
    同じ「標準偏差」でも、どれを使ったかで数字が変わります。**どちらを使ったかを書いてください。**

**最頻値も既定がちがいます。**同率が2つあるとき（`[1,1,2,2,3]`）、
`MODE.SNGL` は**1つだけ**返し、pandasの `mode()` は **`[1, 2]` と両方**返します。

## 第5回 調査の実施・回収記録 { #w05 }

| 概念 | Excel | ノートブック |
|---|---|---|
| 回収件数 | `COUNTA`（空欄を除いて数える） | `len(mydf)`／`notna().sum()` |
| 重複した回答を外す | データ → **重複の削除** | `drop_duplicates()` |
| 日付で並べる | 並べ替え | `sort_values("タイムスタンプ")` |

!!! danger "🔴 Excelの「重複の削除」は、元の表から消します"
    **消えた行は戻りません**（取り消すしかありません）。
    `drop_duplicates()` は**新しい表を返す**ので、元の `mydf` はそのまま残ります。

!!! quote "実際にあったこと（国際会議の託児の運営から）"
    申込の一覧を、**登録システムが出力するCSVとは別に、手で作って**いました。
    その一覧で、**あるお子さんの姓が、別の家族の姓になっていました。**手で打ち直した跡です。

    問題は、打ちまちがいそのものではありません。
    **その名前が、日別の部屋割り・食事の数・配置の表に、何度も書き写されていた**ことです。
    1つの資料の中だけで**7か所**。**1か所直しても、残りは直りません。**

    登録のほうを直しても、手で作った一覧には**何も起きません。**
    結局、**全部を手で直して回る**ことになります。そして、直し忘れた1か所が当日に残ります。

    🔴 **残った1か所は、読む人には見分けがつきません。**
    その表を見た人は、**まちがいだと気づかないまま、そのとおりに動きます。**
    今回の行には持病が書いてありました。**その子に起きうることが、別人の名前で並んでいた**わけです。
    薬や食事やアレルギーの話であれば、そのまま事故になります。

    **いちばん効いてくるのは、火事や地震が起きたときです。**
    避難したあと、**その子が誰で、どの連絡先の家の子なのか**を、名前でたどることになります。
    名前が別人のものになっていれば、**たどれません。**
    親に「お子さんは無事です」と伝えることが、**できなくなります。**

    名前は、ただの文字ではありません。**子どもと親をつなぐ、鍵**です。
    手で打ち直すというのは、**その鍵を、毎回作り直している**ということです。

    直したのは、一覧の作り方のほうです。**CSVから出し直す。**
    出し直せば、**直すのは登録の1か所だけ**で、表は全部そろいます。

    そこから出てきた問い方が、これです ――
    **「その一覧は、システムから出力されますか。手で作りますか。」**

**これを数字で見たのが、第6回の資料の D です。**
設問が1つ増えたときの操作は、**Excel 34回／ノートブック 0回**でした
（[同じ課題をExcelでやると](week06-excel.md)）。
あちらは「列が増えたとき」、ここでは「1件直したとき」。
**どちらも、手で作った表には変更が伝わらない**という、同じ形です。

!!! quote "数字を手で打ち直さない"
    **これはExcelかノートブックかの話ではありません。**
    CSVを開いて数字を手で直した時点で、それは**集めたデータではなく、打ち直した人の記憶**になります。

    直すなら、**元データは残したまま、直す手順のほうを残す。**
    （第6回でやった `=IF(...=-999,"")` も `replace(-999, pd.NA)` も、やっていることはこれです）

## 第7回 クロス集計 { #w07 }

| 概念 | Excel | ノートブック |
|---|---|---|
| クロス集計表（分割表） | **ピボットテーブル**／`COUNTIFS` | `pd.crosstab(A, B)` |
| 行の% | 値の表示方法 → **行集計に対する比率** | `normalize="index"` |
| 列の% | 値の表示方法 → **列集計に対する比率** | `normalize="columns"` |
| 全体の% | 総計に対する比率 | `normalize="all"` |
| 層別（3つめの項目で分ける） | フィルターに3つめのフィールドを置く | `groupby("層")` して同じ表を作る |

**Mac版では、右クリックのメニューに全部が出ないことがあります。**そのときは「その他のオプション」から選びます。

!!! warning "🔴 どちらで割ったかを書く"
    「行の%」と「列の%」は、**同じ表から出る、別の話**です。
    Excelでもノートブックでも、**選んだのは人間**です。だから**どちらで割ったかを書く**。
    書いていない%は、読む人が確かめられません。

**ピボットテーブルを使わない理由は、「できないから」ではありません。**
マウスで作った表は、**記録しておかないと、あとからどう作ったか言えない**からです
（[過程が残る道具を使う](process.md)／[マクロで記録すれば残せる](week06-excel.md#macro)）。
