    第8回 資料 Colabで詰まるところ一覧¶

    このページは、毎回の作業中に開いておくためのものである。 ここに載っているのは、実際にこの授業で起きたものだけである。

    使い方

    詰まったら、まず症状で探す。 見つからなければ、エラーの文をそのままコピーしてAIに貼る。 それでも動かないときに、TAか教員に声をかける。そのとき「どこまでできて、どこで止まったか」を言えると早い。

    1. ファイルを入れる前後¶

    症状 原因 直し方
    FileNotFoundError: No such file or directory: '/content/○○.csv' CSVがColabに入っていない 下の「入れ方」のとおりに入れてから、読み込みのセルを押す
    入れたはずなのに FileNotFoundError 🔴 思ったのと違う場所に入っている／ファイル名の打ち間違い 下の「パスをコピーして貼る」。手で打たない
    さっきまで動いていたのに、急に FileNotFoundError Colabを閉じるとアップロードしたファイルは消える 開き直したら、アップロードからやり直す。上から順に ▶ を押し直す
    読み込めない／列がぐちゃぐちゃ .xlsx のまま読もうとしている 元の表で「名前を付けて保存」→ CSV（UTF-8）で書き出す
    日本語が � や 譁�蟄怜喧 になる 文字コードが違う（Excelで開いて保存し直すと起きやすい） 元のFormsから書き出し直す。手元のファイルを直そうとしない

    🔴 CSVの入れ方と、ファイル名の貼り方¶

    「入れたはずなのに見つからない」が、いちばん多い。原因は2つあり、どちらもやり方で防げる。

    入れ方 ―― ドラッグしない¶

    🔴 ファイルをドラッグして落とすのは、やめてください。 フォルダの上に落ちると、その中に入ってしまいます。/content/○○.csv のつもりが /content/sample_data/○○.csv になり、見つからなくなります。画面上はどちらも同じように見えます。

    1. 左の 📁（フォルダのアイコン）を開く
    2. 上にある 「セッション ストレージにアップロード」（↥ のアイコン）を押す
    3. CSVを選ぶ

    ファイル名 ―― 手で打たない¶

    Formsから落としたCSVは 調査(1-37).csv のように、日本語・括弧・スペースが入ります。手で打てば、まず合いません。

    1. 入ったCSVの行を 右クリック
    2. 「パスをコピー」
    3. pd.read_csv("　") の引用符の中に貼り付ける（中身は全部消してから貼る）
    mydf = pd.read_csv("ここに貼り付ける")

    貼り付けたパスを見れば、どこに入っているか分かる

    /content/調査.csv … 正しい場所にある /content/sample_data/調査.csv … 🔴 フォルダの中に入っている （貼ったパスのままでも動きます。気持ち悪ければ、入れ直してください）

    ファイル名を打ち直さない。これも「数字を手で打ち直さない」と同じ話です。

    🔴 読み込んだら、まず確かめる¶

    read_csv を押したすぐ後に、これを1回実行する。30秒で済む。ここを飛ばすと、あとで必ず戻ってくることになる。

    # ① そもそもファイルがColabに入っているか
!ls /content

    入れたはずのCSVの名前が出てこなければ、まだ入っていないか、フォルダの中に入っている。上の「入れ方」からやり直す。 （! で始まる行は、Pythonではなくコンピュータへの命令である。詳しくは第9回で。）

    # ② 読めたか ―― 行数・列数と、中身の型を見る
print("行数・列数:", mydf.shape)        # (回答数, 列数)。行数が 0 なら読めていない
print()
print(mydf.head(3))                     # 最初の3行。見出しが1行目に来ているか
print()
print(mydf.dtypes.to_string())          # object = 文字列。数のはずの列が object なら、文字が混ざっている

    # ③ 中身が入っているか ―― 回答が1件もない列を探す
print("回答数:", len(mydf))
print()
empty = [c for c in mydf.columns if mydf[c].notna().sum() == 0]
print("🔴 全部空の列:", empty if empty else "なし")
print()
print("列ごとの回答数")
print(mydf.notna().sum().to_string())

    ③で名前が出るのは、たいてい無害な列である。Formsの書き出しには 名前・最終変更時刻 のような最初から空の列が必ず付いてくる。フォームを「クイズ」形式で作った班には、合計点数・クイズのフィードバック・フィードバック - ○○ という空の列も付く。どれも無視してよい。

    自分が使いたい設問の列が③に出たときだけ、班で元のFormsを確認する。

    ③の結果 意味 どうするか
    名前・最終変更時刻・合計点数 などが出た Formsが付けた列。最初から空 無視してよい
    使いたい設問の列が出た その列には回答がない 班で元のFormsを確認する
    回答数が思ったより少ない 書き出した時点の回答数。締め切り前のものかもしれない 班で、いつ書き出したものか確かめる

    🔴 head() の5行だけで「空だ」と決めない

    mydf.head() は最初の5行しか表示しない。そこが空欄でも、下のほうには入っていることがある。 実際、このクラスにも先頭5行だけが空欄という列がある。全体では37件中28件に回答が入っているのに、 5行だけを見れば「この列は空だ」と判断してしまう可能性がある。 空かどうかは、必ず上の notna().sum() で数える。

    # ④ 表をExcelのように見る（第7回でやったもの）
#    🔴 見るだけ。ここで直してはいけません。
from google.colab import sheets
sheet = sheets.InteractiveSheet(df=mydf)

    並べ替えたり、端まで見たりできるので、どんなデータなのかを掴むのに向いている。 初回は Google ドライブへの許可を聞かれ、許可すると自分のドライブにシートが1枚できる。

    🔴 このシートを手で直しても、mydf は変わりません

    画面の見た目が変わるだけです。「直したのに結果が同じ」の原因になります。 直すのはコードでやってください。 そもそも、手で打ち直した時点で、それは元データではなくなります。（第6回でやったとおり）

    見終わったら、そのシートは消してよい

    班の回答データを、個人のドライブに置いたままにしないでください。 回答の置き場所については、第2回の資料（どこまで言えるか）のとおりです。

    🔴 書き出したCSVは「コピー」である

    回答そのものはForms側にある。手元のCSVが壊れたら、直すより書き出し直すほうが速くて確実。 逆に、Excelで開いて手で直したCSVは、もう元データではない。 （見出しが Column のような名前に変わっていたら、誰かが手で編集した跡である）

    2. 列を指定するとき¶

    症状 原因 直し方
    KeyError: '○○'。列名は合っているはずなのに 🔴 列名に見えない文字が入っている 下の「列名を掃除する」を実行する
    列名の表示に \n や \xa0 が見える 改行とノーブレークスペース。Formsの書き出しではほぼ必ず入る 同上
    表が空（Empty DataFrame）になる／件数が全部 0 になる 🔴 区分にまとめた結果を、元の列に書き戻している（下の §4 を見る）。まれに、その列に回答がない まず pd.read_csv のセルを押し直す。区分は新しい名前の列に入れる。回答の有無は mydf[col].notna().sum() で数える 
    # 列名を掃除する ―― 列を指定する前に、1回だけ実行する
print(mydf.columns.tolist())          # ← まず実物を見る

mydf.columns = (mydf.columns
                .str.replace("\n", "", regex=False)   # 改行を消す
                .str.replace("\xa0", "", regex=False) # ノーブレークスペースを消す
                .str.strip())                          # 前後の空白を消す

print(mydf.columns.tolist())          # ← きれいになったか確かめる

    3. 値の中身¶

    症状 原因 直し方
    平均を出そうとして TypeError: Could not convert string ... to numeric 数値の列に文字が混ざっている（「60」と「60分」） ① どの回答が原因か実物を見る → ② 直す。いきなり消さない
    value_counts() で、同じはずの値が2行に分かれる 🔴 半角と全角が混ざっている（3 と ３） 消さずに、半角にそろえる（unicodedata.normalize("NFKC", s)）
    並べ替えると、1つだけ変な場所に出る 同上。全角は数ではなく文字なので、後ろか別扱いになる 同上
    選択肢がラベルごと入っている（「1：全く当てはまらない」） Formsの選択肢の書き方 先頭の数字だけ取り出す／対応表で数値に直す
    件数が思ったより少ない 空欄（NaN）が自動で除かれている それでよい。ただし 何件から出した数字かを必ず書く

    🔴 「数字以外を全部消す」はやってはいけない

    どの回答が原因かを見ないまま消すと、消してはいけないものまで消える。 順番は ① 犯人を探す → ② 直す。

    4. セルを押すとき¶

    症状 原因 直し方
    ▶ を押しても何も起きない。エラーも出ない 行の先頭に # が付いたまま。# の行は実行されない 使う行の # を消す。何も起きないのが正常
    書き換えたのに、出力が前のまま 🔴 書き換えたあとに ▶ を押していない もう一度 ▶ を押す。出力は、最後に押したときのもの
    2回目に押したら、件数が全部 0 になった 🔴 元の列に結果を書き戻している 新しい名前の列に入れる（mydf["○○_区分"] = ...）。何回押しても同じ結果になる
    NameError: name 'mydf' is not defined 読み込みのセルより前のセルを押した／ランタイムが切れた 上から順に ▶ を押し直す。セルの位置が読み込みより前なら、後ろに動かす

    5. コードを書くとき¶

    症状 原因 直し方
    SyntaxError: invalid non-printable character U+3000 🔴 コードに全角スペースが入っている。画面では空白にしか見えない その行の空白をいったん全部消して打ち直す。行の末尾に入っていることが多い
    SyntaxError: invalid character '”' (U+201D) など 全角のクォートやカッコ（” （） 半角に打ち直す

    どちらも、エラーの文をそのままAIに貼れば一発で分かる。 実際にこのクラスで起きたときも、AIは「行の末尾に全角スペースが入っています」と正しく答えた。

    6. 🔴 最後に ―― これはエラーが出ない¶

    AIが出した数字を、自分のセルの出力と見比べずに書き写す。

    これはエラーになりません。画面は何も言いません。けれど、間違っています。

    実際にこの授業で起きました。同じデータ・同じ件数なのに、報告された平均が2つあった。 片方は自分のノートブックで計算した数字、もう片方はAIが出した数字で、AIのほうが誤っていた。 手元に出力があれば、その場で気づけた。

    AIに計算させてよい。ただし、自分のセルの出力と見比べてから書く。 見比べられる形で残っていないものは、まだ結果ではない。
