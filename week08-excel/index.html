    第8回 資料 同じ概念を、Excelではどう扱っているか¶

    この回でやる「並べ替え」と「順位」は、Excelにも同じものがあります。 名前と既定値がちがうだけです。どちらが優れているかの話ではありません。

    これは補習です（成績には入りません）

    読まなくても課題8は出せます。課題8に出すものは変わりません。

    ここに置いたのは、「Excelならどうやるのか」を並べて見るためです。 ノートブックで書いたコードと、Excelの関数を突き合わせると、どちらの意味も分かります。 片方しか知らないと、「そういうものだ」で終わってしまいます。

    1. 概念の対応表¶

    この回でやること Excel ノートブック（pandas）
    行を並べ替える データ → 並べ替え（元の表が並べ替わる）／SORT 関数（並べ替えた新しい表が出る） sort_values("体重g", ascending=False)
    複数のキーで並べ替える 並べ替えダイアログの「レベルの追加」 sort_values(["科","体重g"], ascending=[True, False])
    順位の数字をつける RANK.EQ／RANK.AVG rank(ascending=False, method="min")
    上位10件だけ見る 並べ替えて上から10行／フィルターの「上位10項目」／LARGE nlargest(10, "体重g")
    グループの中での順位 COUNTIFS で数えて作る（下の4） groupby("科")["体重g"].rank(...)
    件数（n）を併記する COUNT／COUNTA、ピボットの「データの個数」 agg(種数="count", 中央値="median")
    科ごとに集計する ピボットテーブル／AVERAGEIFS・MEDIAN＋条件 groupby("科")["体重g"].median()

    順位が差の大きさを消すことも、件数の少ない順位がぶれることも、道具とは関係ありません。 Excelで作っても同じです。だから「実数を併記する」「nを書く」は、どちらでやるときも同じように必要です。

    2. 🔴 いちばん大事なちがいは、同順位の既定値です¶

    同じ値が並んだとき、順位をどう振るかは1通りではありません。

    体重が 30, 20, 20, 10 の4件を、重い順に並べたとします。20が2件で同じです。

    考え方 20の2件に付く順位 Excel ノートブック
    同じ値は同じ順位。次は飛ばす 2位・2位（次は4位） RANK.EQ rank(method="min")
    同じ値は平均の順位 2.5位・2.5位 RANK.AVG rank(method="average") ← pandasの既定

    既定値が逆になっています

    Excelでよく使う RANK.EQ は「同じ順位・次は飛ばす」。 pandasの rank() は、何も書かなければ「平均の順位」。

    つまり method= を書かずに rank() を使うと、Excelと答えがちがいます（2 対 2.5）。 授業のノートブックが method="min" と書いてあるのは、RANK.EQ と同じにするためです。

    手元で確かめた結果（pandas 2.3.3、[10, 20, 20, 30] を降順）： min → 4, 2, 2, 1 ／ average → 4, 2.5, 2.5, 1 ／ dense → 3, 2, 2, 1

    同値が多いデータでは、この差がそのまま結果の差になります。 アンケートの5段階評価は同値だらけです。順位を出す前に、同じ値が何件あるかを数えてください。

    3. 並べ替えは、Excelでは「元の表を書き換える」¶

    ここが、いちばん事故が起きるところです。

    Excelの「データ → 並べ替え」 SORT 関数 sort_values()
    元の並び 消える（戻すには取り消しか、連番の列） 残る 残る
    結果の置き場所 同じ場所（上書き） 別の場所に新しい表が出る 新しい表が返る

    SORT 関数は「並べ替えた配列を返す」関数で、元の範囲は並べ替えません（Microsoft 365・2021・2024、Mac版でも使えます）。 =SORT(A2:C100, 3, -1) で「3列目の降順」です。考え方は sort_values() と同じです。

    🔴 1列だけ選んで並べ替えると、行の対応が壊れます

    体重の列だけを選んで並べ替えると、体重だけが動いて、名前はその場に残ります。 「サル名」と「体重」の組み合わせが、全部ちがうものになります。

    エラーは出ません。表は何ごともなく表示されます。平均もそのまま出ます。 Excelは「選択範囲を拡張しますか」と聞いてくることがありますが、聞かれない場合もあります。

    ノートブックの sort_values() は行ごと動くので、この壊れ方はしません。 かわりに、ノートブックには元の列に書き戻すと2回目に壊れるという別の事故があります。

    道具を変えると、事故の形が変わるだけです。どちらも、結果を見て気づけません。

    Excelで並べ替えるときの定石

    並べ替える前に、1, 2, 3, … の連番の列を1本作っておく。 それで元の順に戻せます。これは「過程を残す」の最小形です。

    4. グループの中での順位は、Excelでは関数を組みます¶

    ノートブックの「科内順位」は groupby("科")["体重g"].rank(...) の1行でした。 Excelの RANK.EQ には「同じ科の中だけで」という指定がありません。だから数えて作ります。

    =COUNTIFS($B:$B, B2, $C:$C, ">"&C2) + 1

    「自分と同じ科（B列）で、自分より大きい体重（C列）が何件あるか」を数えて、1を足す。 これが「科の中での順位」です。RANK.EQ と同じ「同じ値は同じ順位・次は飛ばす」になります。

    式の形はちがいますが、やっていることは同じです。 「順位とは、自分より上が何件あるかを数えたもの」――これが順位の定義そのものです。

    5. 全角数字は、どちらでも事故になります。ただし壊れ方がちがう¶

    ３（全角）と 3（半角）は別の文字です。画面では見分けがつきません。

    何が起きるか 気づけるか
    Excel 全角のままだと文字列として扱われる。昇順では数値が先、文字列があとに並ぶ（空白セルは常に最後） 並べ替えると下のほうにまとまって残るので、見れば分かる
    ノートブック pd.to_numeric(..., errors="coerce") が全角を黙って欠測（NaN）にする 何も出ない。件数を数えないと気づけない

    文字列として並べ替えると、10 が 3 より先に来ます（1文字目の 1 と 3 を比べるため）。 手元で確かめた並び順：['10', '3', '３']。これは「数の順」ではありません。

    直し方

    • Excel：列を選んで、表示形式を数値にそろえる（Microsoftの説明では「すべてを数値またはテキストのどちらかに書式設定する」）。 =VALUE(ASC(A2)) でも半角の数値にできます
    • ノートブック：.str.normalize("NFKC") を通してから to_numeric。そのあと必ず件数を出す

    並べ替えは、この種の汚れをいちばん早く表に出す作業です。今日やるのはそれでもあります。

    6. やってみる（任意）¶

    同じランキングを、両方で作って突き合わせてください。ずれたら、どちらかの既定値がちがっています。

    1. 練習用データ（primates.csv）をExcelで開く
    2. 体重gの降順で並べ替え、上から10件を見る（SORT 関数でもよい）
    3. ノートブックの df.nlargest(10, "体重g") と同じ10種・同じ順番になるか確かめる
    4. ちがったら、欠測（空欄）の扱いと同順位の扱いを見る

    数字が合ったことより、「なぜ合うのか」が言えることのほうが大事です。 3通りで出して突き合わせるやり方は、第6回の資料に書いてあります。

    出どころ¶

    • RANK.EQ 関数（Microsoft） ／ SORT 関数（Microsoft）
    • Excel の範囲または表のデータを並べ替える（Microsoft）（既定の並べ替え順序・数値と文字列が混在する場合）
    • pandasの既定値は、この資料を書くときに実行して確かめました（pandas 2.3.3）
